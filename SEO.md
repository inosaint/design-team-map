# SEO Landing Pages

Org Mapper is a client-only Vite/React SPA with a single `index.html` and no
router, so there was no way for search engines to index anything about
specific use cases. This adds one static, crawlable landing page per
industry/occupation.

## What exists

11 static pages under `public/{slug}-org-chart/index.html`, served at
`/{slug}-org-chart/` (trailing slash):

`design`, `engineering`, `product`, `sales`, `marketing`, `hr`, `finance`,
`healthcare`, `legal`, `construction`, `education`.

Each page has:
- `<title>` / `<meta name="description">` / `<link rel="canonical">` / Open
  Graph + Twitter card tags, all industry-specific.
- A real screenshot of an example chart for that industry (`webp` primary via
  `<picture>`, `png` fallback), or a generic placeholder icon for any industry
  without one yet.
- Two CTAs: **"See a live \{industry\} example"**, which opens the app with a
  pre-filled, auto-arranged 3-person example chart for that industry via the
  `?chart=` URL import (see below); and **"Try for free"**, linking to `/`.
- A two-column list of that industry's career levels and common role types.
- A footer cross-linking to the other 10 pages (so crawlers have a path
  between them beyond the sitemap).

`public/sitemap.xml` and `public/robots.txt` list all 11 pages plus `/`.

## Why trailing-slash URLs

Each page is `public/{slug}-org-chart/index.html`, not
`public/{slug}-org-chart.html`. Static hosts (Vercel/Netlify) resolve a
directory's `index.html` for a clean `/{slug}-org-chart/` request by default.
All internal links (canonical, `og:url`, sitemap, footer cross-links) use the
trailing-slash form consistently, since that's what actually resolves against
real static-file serving — a no-trailing-slash request or a bare directory
request without an `index.html` falls back to the SPA shell instead.

Vite's own dev server doesn't do directory-index resolution the way a real
static host does, so `vite.config.ts` adds a small dev-only middleware plus
`appType: 'mpa'` to make `npm run dev` behave the same way locally.

## Regenerating the pages

All 11 pages, plus `sitemap.xml`/`robots.txt`, are generated by
[`scripts/generate-seo-pages.mjs`](scripts/generate-seo-pages.mjs):

```bash
npm run generate:seo
```

The script embeds each industry's full preset data (role types, career
levels — mirroring `INDUSTRY_PRESETS` in
`src/components/QuickstartWizard.tsx`) so the "Career levels"/"Common roles"
lists and the live example chart are accurate per industry, not generic
filler.

To point the generated links at a local dev server instead of production
(e.g. to click through the "See a live example" CTA against `localhost`
while testing), set `SEO_SITE`:

```bash
SEO_SITE=http://localhost:5173 npm run generate:seo
```

Always re-run `npm run generate:seo` (with no `SEO_SITE` override) before
shipping, so the committed pages point at `https://mapyour.org`.

## Adding a real example screenshot for an industry

Currently, adding a screenshot for an industry not yet covered (or replacing
an existing one) is a manual step:

1. Drop the raw screenshot at `public/{slug}-org-chart/{slug}-org-chart.png`.
2. Resize it to a reasonable web width and generate a `webp` copy:
   ```bash
   cd public/{slug}-org-chart
   sips -Z 960 {slug}-org-chart.png --out {slug}-org-chart.png
   cwebp -q 82 {slug}-org-chart.png -o {slug}-org-chart.webp
   ```
3. Add a `chartImage: { file: '{slug}-org-chart/{slug}-org-chart', width, height }`
   entry to that industry's object in `scripts/generate-seo-pages.mjs` (use
   the post-resize dimensions from `sips -g pixelWidth -g pixelHeight`).
4. Re-run `npm run generate:seo`.

Without a `chartImage` entry, the page falls back to the generic
`design-team-mapper.png` icon.

## The `?chart=` URL import feature

The "See a live example" CTA doesn't just link to a static description of a
chart — it opens the actual app pre-loaded with a real, auto-arranged example
chart, via a `?chart=` URL parameter that any agent, script, or landing page
can use. This is documented for external/agent use in the main
[`README.md`](README.md#loading-a-chart-via-link-for-ai-agents--automation);
the implementation lives in `src/utils/importData.ts` (encode/decode +
validation) and `src/App.tsx` (reads the param on mount, imports it via the
same store action the file-based JSON import uses, and auto-arranges the
chart if no explicit positions were supplied).
